# ADR-027: Agent-to-Agent Communication over Zenoh Pub/Sub

**Status:** Accepted
**Date:** 09-06-2026
**Author:** Abel-Raul Mazilu

---

## Context

Issue #116 required two LLM-backed agents to hold a structured, multi-turn dialogue, so I wanted to make a "council" and produce a synthesized answer to a user query. The dialogue needed to run over the existing Zenoh mesh so that it inherits the platform's transport security (mTLS, ADR-003) and router topology without adding a new broker or sidecar.

Several design questions had to be settled:

- **Transport primitive** — Zenoh exposes both pub/sub (put/subscribe) and queryable (get/reply). Which fits a turn-based dialogue?
- **Topic shape** — a shared channel with routing headers, or a dedicated inbox per agent?
- **Wire format** — plain text, a generic envelope, or a typed message struct?
- **LLM coupling** — embed the HTTP client in each binary, or share it?
- **Conversation modes** — should agents always deliberate, or only on demand?

## Decision

### Crate layout

Three new crates under `src/`:

| Crate | Kind | Role |
|---|---|---|
| `a2a` | library | Shared wire type (`A2AMessage`), LLM clients (`OllamaClient`, `ClaudeClient`), topic constants |
| `agent_a` | binary | Initiator: interactive REPL, publishes to Agent B, receives replies, runs synthesis |
| `agent_b` | binary | Responder: subscribes to its inbox, calls LLM, publishes reply to Agent A |

### Transport: pub/sub, not queryable

Agents communicate via `session.put(inbox_topic, payload)` and `session.declare_subscriber(own_inbox)`. Zenoh's queryable/get primitive was rejected — it couples the caller to a live reply handler and enforces a single-round request/response shape. The dialogue is multi-turn and asynchronous; each side produces output independently before the other responds. Pub/sub makes each message delivery unconditional and lets either side process at its own pace.

### Topic structure: per-agent inboxes

```
dverse/a2a/agent-a/inbox   ← Agent B writes here
dverse/a2a/agent-b/inbox   ← Agent A writes here
```

Each agent subscribes **only to its own inbox**. A single shared topic with a `to` header was rejected: it would require every subscriber to deserialize and discard messages not addressed to it, and it would prevent per-agent ACL rules in the Zenoh router config.

### Wire format: `A2AMessage` JSON

```rust
pub struct A2AMessage {
    pub id: String,          // "{from}-turn{turn}-{unix_secs}"
    pub from: String,
    pub to: String,
    pub content: String,
    pub thinking: Option<String>,  // <think>…</think> if present
    pub timestamp_secs: u64,
    pub turn: u32,
}
```

Serialized to JSON bytes via `serde_json` before publishing. The `thinking` field carries raw chain-of-thought output from models that emit `<think>…</think>` blocks (e.g. DeepSeek-R1), making reasoning visible on both sides of the dialogue without altering the `content` field.

### Three system-prompt modes

Agent A operates in three contexts, each with its own system prompt:

| Mode | Trigger | Prompt role |
|---|---|---|
| **Direct** | plain user input | Single-agent answer; hints that `/zenoh` starts a council |
| **Council** | `/zenoh <query>` prefix | Peer deliberation; 2-3 sentences per turn, intellectually rigorous |
| **Synthesis** | after all council turns | Produce a unified answer from the turn transcript |

The `/zenoh` prefix makes council mode opt-in. Users interacting with Agent A get fast direct answers by default and invoke the multi-agent path explicitly when they want it.

### Turn loop and timeout

`run_council` in `agent_a` drives the exchange:

1. Agent A generates a council contribution and publishes it to `AGENT_B_INBOX`.
2. Agent A waits on its inbox channel with a 60-second `tokio::select!` timeout.
3. On receipt, Agent B's reply is appended to `council_history` and the next turn begins.
4. After all turns (configurable via `--turns`, default 2), Agent A calls the synthesis prompt and returns the consensus to the REPL.

The 60-second timeout prevents the REPL from hanging indefinitely if Agent B is unreachable. On timeout, synthesis runs on whatever partial transcript exists.

### LLM backend

Default: `OllamaClient` targeting `deepseek-r1:1.5b` at `http://localhost:11434`. Both `--ollama-url` and `--model` are CLI flags so any Ollama-compatible model can be substituted at runtime without recompilation. `ClaudeClient` (Anthropic HTTP API) is available in the `a2a` crate for cloud-backed deployments but is not the default — it requires `ANTHROPIC_API_KEY` and incurs per-token cost.

## Alternatives

**Zenoh queryable for each agent.** Rejected. Queryable enforces a synchronous request/reply round; it cannot represent a turn-based dialogue where each agent generates output independently and the exchange spans multiple rounds.

**Single shared topic `dverse/a2a/messages` with a `to` field.** Rejected. Every subscriber would deserialize every message to check the `to` field. Per-agent inboxes allow the router ACL to enforce delivery boundaries without application-layer filtering.

**Plain-text payloads.** Rejected. Untyped payloads make it impossible to carry metadata (turn number, sender identity, reasoning text) without ad-hoc parsing. A shared typed struct keeps the contract explicit and versioned.

**Embed LLM client in each binary separately.** Rejected. Two copies of the same HTTP client struct diverge silently. The shared `a2a` library crate is the single definition point; both binaries take a compile-time dependency on it.

**Always-on council mode (no direct mode).** Rejected. Council mode requires Agent B to be running. A direct mode lets Agent A function as a standalone assistant when Agent B is absent, and keeps latency low for simple queries.

## Consequences

### Positive

- The exchange runs entirely over the existing Zenoh mesh — no new transport, no additional auth surface.
- Per-agent inbox topics are ACL-addressable in the router config.
- `A2AMessage.thinking` makes chain-of-thought reasoning observable across the wire without polluting `content`.
- `/zenoh` opt-in keeps Agent A usable as a single-agent assistant when Agent B is down.
- Shared `a2a` crate prevents LLM client drift between the two binaries.
- Synthesis prompt produces a single coherent answer from the transcript rather than exposing raw back-and-forth to the user.

### Negative

- Turn-based pub/sub is not back-pressured — if Agent B is slow, Agent A's 60-second timeout is the only flow-control mechanism.
- Council history grows unbounded within a session; there is no trimming strategy for very long exchanges.
- Adding a third agent requires a new inbox topic, a new binary crate, and explicit wiring in the initiator's turn loop. The current design does not generalize to N agents without further work.
- `OllamaClient` requires a locally running Ollama instance; the binary silently fails at runtime if the model is not pulled.
